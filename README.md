# CertainlyOpenYoutubeShorts

YouTube チャンネルの Shorts 一覧でサムネイルをクリックしたとき、**クリックした Short ではなく別の Short が再生される**現象を是正する Firefox 拡張機能。

対処している症状は 2 つ。

1. クリックした Short と違う動画が再生される
2. 正しい動画だが**画面が真っ黒で音声だけ流れる**

あわせて、クリック後の再生順を**チャンネル一覧で選んでいた並び順**（新しい順／人気の動画／古い順）に保つ。

対策は三段構え。**予防**で原因の経路そのものを断ち、**順送り**で並び順を保ち、**是正**を安全網として残す。

ライセンスは [MIT](LICENSE)。情報の収集・送信は一切行わない（[プライバシーポリシー](PRIVACY.md)）。

## 使い方

インストールするだけで動く。設定画面は無い。

ただし**ひとつだけ設定が要る**。この拡張機能は Shorts を通常のページ遷移で開くため、
Firefox の自動再生ブロックが働いて再生が止まる。

1. YouTube を開いた状態でアドレスバー左端のアイコンをクリック
2. 「自動再生」→「音声と動画を許可する」

### 既知の制限

Shorts を 1 本送るたびにページ遷移が発生するため、素の状態より動作が遅い。
不具合の原因である SPA 遷移を避けることと引き換えの仕様。
`cys.js` の `自前で順送り` を `false` にすれば、順送りだけ切って YouTube の推薦順に戻せる。

## 再生順の制御

チャンネル一覧の並び順に従った再生は、本来サムネイルが持つ `sequenceParams` で実現されている
（人気の動画順の 17 番目で `reel_watch_sequence` を叩くと応答の先頭が 18 番目になることを実測で確認）。

しかし `sequenceParams` は **SPA 遷移のメモリ上の状態としてのみ運ばれ、URL には乗らない**。
予防（クリックを通常のページ遷移に置き換える）とは両立しない。

そこで一覧の並びを自分で記憶し、次へ／前へ送る操作を横取りして自分で遷移する。

- 一覧でクリックした時点で、表示中の並び順そのままに動画 ID を記憶する（`sessionStorage`）
- Shorts ページでは、ホイールと `ArrowDown` / `ArrowUp` を横取りして記憶した順に遷移する
- 描画済みの分を使い切ったら、チャンネルページを取り直して並び順どおりに一覧を延長する
- 記憶に無い動画（一覧以外から開いた Short）では何もせず YouTube に任せる
- 先頭より前へは戻らない

**引き換えに、1 本送るたびにページ遷移が発生する。** Shorts をテンポよく送る用途では明確に遅くなる。
`cys.js` の `自前で順送り` を `false` にすれば、この機能だけ切れる。

## 予防: SPA 遷移をやめる

Shorts へのリンクのクリックを横取りし、通常のページ遷移（`location.assign`）で開く。

不具合は SPA 遷移の経路でのみ発生し、URL の直接オープン・「リンクを新しいタブで開く」・
是正によるフルロードでは一度も再現していない。SPA セッションに溜まった前の Short の状態が
原因なので、経路を変えれば症状 1 も症状 2 も同時に断てる。

`window` の捕捉フェーズは伝播の最初なので、`document` 以下にある YouTube 側のハンドラより先に止められる。
中クリックや Ctrl/Shift クリックは既定の動作に任せるため、「新しいタブで開く」は従来どおり使える。

`cys.js` の `常に通常遷移` を `false` にすると予防を切り、後述の是正だけで動く。

**引き換えに遷移が少し遅くなる。** また、フルロードにはユーザー操作の履歴が無いため
Firefox の自動再生ブロックが働く。後述の「自動再生を許可」を必ず設定すること。

## 症状 1: 別の動画が再生される（是正）

`/shorts/<ID>` に着地した直後、**ユーザーが何も操作していないのに別の ID へ移動した**場合に、元の ID へフルロードで戻す。

- 監視するのは着地から 4 秒間だけ。
- ホイール・キー入力・タップなどユーザー操作があった時点で監視を解除するため、自分でスワイプして次へ送る動作は妨げない。
- 異常を検知しても即座には戻さず 400ms 待つ。**YouTube 自身が元に戻すことがある**ため、その場合は介入しない。
- 一度戻しても再び移動する場合は、それ以上介入しない（再読み込みループの防止）。

クリックを毎回フルロードに置き換える方式は採っていない。症状が間欠であるため、
普段は SPA 遷移の速度を保ち、外れたときだけ復帰させる。

## 症状 2: 画面が真っ黒で音声だけ流れる（是正）

再生中の映像が表示領域から**完全に外れている**ときだけ、中央に引き戻す。
一部でも見えていればスワイプ途中とみなして触らない。連続発火しないよう 3 秒の間隔を置く。

### 原因

デコードにも CSS にも異常はなく、**スクロール位置だけが追随していない**。

実測値（表示領域 1920x947 のとき）。

```
#1 解像度=608x1080 復号=534 readyState=4 再生 位置=(793,7867) 枠=479x851
   display=block visibility=visible opacity=1
主役が画面外 中心=(1032,8293) 表示領域=1920x947
実表示カード=-1
```

映像は正常に復号され（534 フレーム）、要素としても正しい大きさを持っているのに、
表示領域の約 7,000px 下に置かれている。カード 1 枚が 851px なので
`7867 ÷ 851 ≈ 9.2`、つまり 10 枚目あたりの位置にありながら、コンテナは先頭を表示したまま。
見えているのは何も無い黒い領域で、音だけが聞こえる。

症状 1 と同じ「プレーヤーが自分の位置を見失う」根を持つ。

なお `実表示カード=-1` という出力は当てにならない。カード数 1 でありながら映像が
y=7867 にあるのは矛盾しており、`ytd-reel-video-renderer` というセレクタが
現在の DOM に合っていないだけと考えられる。判断の根拠は `getBoundingClientRect` の実測値。

## 動作確認（v0.3.0 / 実測）

3 分間の実地テストで自動移動を 3 回捕捉し、判断はすべて妥当だった。

| 検知内容 | 判断 | 結果 |
| --- | --- | --- |
| 2124ms で `PvCOcWP5AxI` → `-pkq4HjIq6Y` | 自己復帰（介入せず） | YouTube 側が戻した |
| 1485ms で `fw_k2enkZig` → `NeDVF-KSgxA` | 自己復帰（介入せず） | YouTube 側が戻した |
| 1431ms で `kJVdncPxo7E` → `BFf4b7opQDw` | **是正実行** | フルロードで `kJVdncPxo7E` が開いた |

400ms の様子見が無ければ、上 2 件で不要な再読み込みが走っていた。誤爆・取りこぼしともに 0。

## 原因

Firefox のみで発生し、Chrome では発生しない。拡張機能を全て無効にした
トラブルシューティングモードでも再現するため、他アドオンの干渉ではない。
発生は間欠で、チャンネルを問わず起きる。

### 直接の引き金

**`reel_watch_sequence` の応答が極端に小さいとき、その直後に必ず自動移動が起きる。**

| 状況 | 応答長 |
| --- | --- |
| 正常 | 285,463 / 293,468 / 490,949 / 502,437 / 503,805 バイト |
| 自動移動の直前 | **11,550 / 11,559 バイト** |

小さい応答の中身は、正常な応答の**並びを逆順にしたもの**。

- `KInCEwgHo4I` の正常応答（285KB）: `LBaX51hw_X0, AafrrpePLq0, rJgMnPbZ00A, to4qvRF1emA, rCDQCIiMuDE`
- 異常応答（11.5KB）: `-pkq4HjIq6Y, rCDQCIiMuDE, to4qvRF1emA, rJgMnPbZ00A, AafrrpePLq0`

上方向スクロール用の「前の動画」リストと考えられる。プレーヤーがこれを取りに行き、
適用先を誤って 1 つ前へ動く。「クリックした動画より前のものが再生される」という症状と一致する。

`再生成功` の対象 ID と URL が食い違う記録も出ており、URL とプレーヤー内部の状態がずれている。
`AbortError` はその結果であって原因ではない。

SPA セッション内に溜まった前の Short の状態が引き金であり、新規ロードにはその状態が無い。
経路ごとの挙動もこれで説明がつく。

| 経路 | 結果 |
| --- | --- |
| URL を直接開く | 正常 |
| 一覧で右クリック →「リンクを新しいタブで開く」 | 正常 |
| 一覧でクリック（SPA 遷移） | **たまに別の Short が再生される** |

### 前提として確認済みのこと

- 一覧のリンク（`href`）と、サムネイルが持つ `sequenceParams` に埋め込まれた `videoId` は**正しい**。
  48 件を照合してズレ 0 件。つまり「リンクを書き換える」対策は無意味。
- Shorts プレーヤーの表示は「URL の `videoId`」＋「`reel_watch_sequence` の応答」の合成で決まる。
- **この応答にはクリックした動画自身が含まれない。先頭は一覧上で次にある動画**。
- シーケンスは**アカウントごとに個人化**されるため、飛び先は一覧上の隣とは限らない。

## 既知の副作用: 是正後に再生が止まる

是正はフルロードで行うため、そのページにはユーザー操作の履歴が無い。
Firefox の自動再生ブロックが働き、`NotAllowedError` で再生が始まらない
（実測では復帰後 12 秒間停止したままだった）。

**YouTube の自動再生を許可すると解消する。**

1. YouTube を開いた状態でアドレスバー左端のアイコンをクリック
2. 「自動再生」→「音声と動画を許可する」

設定から入る場合は、設定 → プライバシーとセキュリティ → 許可設定 → 自動再生「設定...」→
`https://www.youtube.com` を「音声と動画を許可する」で追加する。

## リリース手順（AMO へ公開する）

一時的なアドオンは Firefox を再起動すると消える。恒久的に配布するには AMO の署名が必要。
掲載フォームに入れる文面は [docs/AMO掲載情報.md](docs/AMO掲載情報.md) にまとめてある。

公開（listed）ではなく自分だけで使いたい場合は、手順 2 で配布方法に
**「自分で配布する」（On your own）** を選ぶ。AMO の一覧には載らず、
審査も自動チェックのみなので通常は数分で終わる。

### 1. パッケージを作る

```
powershell -ExecutionPolicy Bypass -File build.ps1
```

`dist\CertainlyOpenYoutubeShorts-<版>.zip` ができる。`manifest.json` が zip の直下にある必要があるため、
エクスプローラーでフォルダを右クリックして圧縮したものは**使えない**（フォルダが1階層挟まる）。

### 2. AMO にアップロードする

1. https://addons.mozilla.org/developers/ で Firefox アカウントを作成しログイン
2. 「新しいアドオンを登録」→ 配布方法を選ぶ
   - **公開する場合**: 「Mozilla で配布する」。審査に回り、AMO の一覧に載る
   - **自分だけで使う場合**: 「自分で配布する」（On your own）。署名済み `.xpi` が数分で手に入る
3. 手順 1 の zip をアップロード
4. [docs/AMO掲載情報.md](docs/AMO掲載情報.md) の文面を各欄に入力（公開する場合のみ）

ソースコードの提出は不要（難読化・minify をしていないため）。

### 3. インストールする

1. `about:addons` を開く
2. 右上の歯車 → 「ファイルからアドオンをインストール」
3. ダウンロードした `.xpi` を選ぶ

以後は Firefox を再起動しても残る。

### 更新するとき

`manifest.json` の `version` を上げてから 1〜3 を繰り返す。AMO は同じ版番号の再アップロードを受け付けない。
新しい `.xpi` を入れれば古い版に上書きされる。

### 注意

- 拡張機能 ID は `certainly-open-youtube-shorts@konamuki0852`。AMO で「ID が既に使われている」と言われたら
  `manifest.json` の `browser_specific_settings.gecko.id` を別の値に変えて再アップロードする。
- `browser_specific_settings.gecko.data_collection_permissions` は AMO の必須項目。
  本アドオンは何も収集・送信しないため `{ "required": ["none"] }` を宣言している。
  これが無いと「The "data_collection_permissions" property is missing.」で検証に失敗する。
- 検証に失敗した版番号は再利用できないことがある。指摘を直したら版番号も上げてから再提出する。
- `build.ps1` は **UTF-8 BOM 付き**で保存すること。BOM が無いと Windows PowerShell 5.1 が
  CP932 として読み、日本語コメント末尾の全角文字が改行を飲み込んで次の行が消える。

## インストール（開発中の一時的な読み込み）

1. Firefox のアドレスバーに `about:debugging#/runtime/this-firefox` を入力
2. 「一時的なアドオンを読み込む...」をクリック
3. このフォルダの `manifest.json` を選択

一時的なアドオンは Firefox を再起動すると消える。常用したい場合は AMO 署名が必要。

**ファイルを更新したら `about:debugging` の「再読み込み」を押すこと。**
押さないと古いコードが動き続ける。読み込まれている版はページのコンソールで確認できる。

```
document.documentElement.dataset.cys
```

## 動かないとき

まず、注入されているかを確認する。ページのコンソールで次を実行する。

```
document.documentElement.dataset.cys
```

版番号が返れば動いている。`undefined` なら注入されていない。

### `undefined` のとき

**同じ ID のアドオンが `about:addons` に残っていないか確認する。** これが最も嵌まりやすい。

無効状態であっても、同じ ID のアドオンが登録されていると
`about:debugging` の一時アドオンは読み込まれない。**エラーも警告も出ない**まま
一覧には表示され、しかし注入だけされない、という壊れ方をする。

署名版を入れた後に一時アドオンへ戻す場合は、`about:addons` から署名版を
**完全に削除**すること。「無効化」では足りない。

その他の確認点。

- `about:debugging` で選ぶのは展開されたフォルダの `manifest.json`。
  `dist` の zip を選ぶと古い版が読み込まれる。
- ファイル構成を変えたときは「再読み込み」ではなく一度「削除」してから読み込み直す。
- コンテンツスクリプトは既に開いているページには後から注入されない。
  読み込み直したら対象のタブを再読み込みする。

## 診断ログ

`F12` でコンソールを開き、フィルタ欄に `CYS` と入力すると記録が流れる。
`window.__CYS.dump()` で全ログを JSON として取り出せる（`window.__CYS.clear()` でリセット）。

| 種別 | 意味 |
| --- | --- |
| `読み込み` | ページ読み込み時の版・URL・タブの可視状態・リファラー |
| `一覧を記憶` | 一覧のクリック時に並び順を記憶した |
| `一覧を延長` | 記憶した一覧の続きを取得した |
| `通常遷移に切替` | Shorts のリンクを横取りしてページ遷移で開いた（予防） |
| `自前で順送り` | 記憶した並び順で次／前の Short へ遷移した |
| `順送りの終端` | 記憶を使い切った。以降は YouTube に任せる |
| `シーケンス` | `reel_watch_sequence` の応答。要求時の ID・応答長・先頭 5 件 |
| `シーケンス異常` | 応答が小さすぎる。**自動移動の前兆** |
| `再生成功` / `再生拒否` | `play()` の結果と、そのときの URL 上の ID |
| `video:error` ほか | `<video>` のエラー系イベント |
| `画面状態` | 着地 3 秒後の映像の状態。黒画面の切り分け用 |
| `画面外を是正` | 再生中の映像が表示領域の外にあったので中央に引き戻した |
| `自動移動を検知` | ユーザー操作なしで別の ID に移った |
| `自己復帰` | 待っている間に YouTube 自身が戻したため介入しなかった |
| `是正` | フルロードで元の ID に戻した |
| `介入中止` | 是正済みの ID が再び移動したため受け入れた |
| `移動を許容` | ユーザー操作による移動、または猶予時間を過ぎた移動 |

ログは `sessionStorage` に保持されるため、ページのフルロードをまたいでも残る。
是正が働いた場合は新しい `読み込み` 行が現れる。

### 黒画面になったとき

音声だけ流れて画面が真っ黒になったら、**その状態のまま**コンソールで次を実行する。

```
window.__CYS.画面()
```

読み方。

| 出力 | 意味 |
| --- | --- |
| `解像度=0x0` または `復号=0` | 映像が復号できていない。デコーダ側の問題 |
| 解像度はあるが `枠=0x0` / `display=none` / `opacity=0` | 復号はできているが表示されていない |
| `実表示カード` が `-1` や想定外の番号 | プレーヤーが別のカードを見せている |

### 隔離環境で完結させている理由

本体は既定の隔離環境（コンテンツスクリプト）で動く。ページ本体の実行環境は使わない。

開発中は、ページと同じ実行環境で `window.fetch` や `HTMLMediaElement.prototype.play` を
フックして計測していた。そのために 2 つの方式を試し、どちらも捨てた。

| 方式 | 結果 |
| --- | --- |
| `<script src="moz-extension://...">` をページに差し込む | **CSP に阻まれる。** YouTube の CSP には `strict-dynamic` が入っており、信頼済みスクリプトが読み込んだもの以外は実行されない |
| manifest の `"world": "MAIN"` | **効かない環境がある。** エラーも警告も出ないまま隔離環境で動き、ページ側からは何も見えない |

原因が判明した後は計測が不要になり、予防・順送り・是正はいずれも
DOM とイベントだけで実現できるため、隔離環境だけで完結する構成にした。
CSP の変更で突然動かなくなる、という壊れ方をしなくなる。

## 調整できる値

`cys.js` の先頭付近。

| 定数 | 既定 | 意味 |
| --- | --- | --- |
| `GRACE_MS` | 4000 | 着地からこの時間内の移動だけを異常とみなす |
| `SETTLE_MS` | 400 | 検知から是正までの猶予。この間に自力で戻れば介入しない |
| `POLL_MS` | 50 | URL の監視間隔 |
| `REPAIR_MEMORY_MS` | 30000 | 同じ ID を直し続けないための有効期間 |
| `SMALL_SEQUENCE_BYTES` | 50000 | これを下回る応答を異常の前兆とみなす |
| `OFFSCREEN_CHECK_MS` | 1000 | 映像が画面外に無いか調べる間隔 |
| `OFFSCREEN_COOLDOWN_MS` | 3000 | 画面外の是正を連続で撃たないための間隔 |
