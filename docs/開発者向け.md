# 開発者向け

利用者向けの説明は [README](../README.md) を参照。
不具合の原因を特定するまでの実測データは [調査記録](調査記録.md) にある。

## 構成

| ファイル | 役割 |
| --- | --- |
| `manifest.json` | アドオン定義（MV3 / Firefox 115 以降） |
| `cys.js` | 予防・順送り・是正・診断の本体。これ 1 本で完結する |
| `icon.svg` | アドオン一覧に出るアイコン |
| `build.ps1` | AMO 提出用 zip を作る（**UTF-8 BOM 付き**で保存すること） |
| `docs/AMO掲載情報.md` | AMO の掲載フォームに入れる文面 |

## 動作の三段構え

### 予防: SPA 遷移をやめる

Shorts へのリンクのクリックを横取りし、通常のページ遷移（`location.assign`）で開く。

不具合は SPA 遷移の経路でのみ発生し、URL の直接オープン・「リンクを新しいタブで開く」・
是正によるフルロードでは一度も再現していない。SPA セッションに溜まった前の Short の状態が
原因なので、経路を変えれば症状 1 も症状 2 も同時に断てる。

`window` の捕捉フェーズは伝播の最初なので、`document` 以下にある YouTube 側のハンドラより先に止められる。
中クリックや Ctrl/Shift クリックは既定の動作に任せるため、「新しいタブで開く」は従来どおり使える。

### 順送り: 一覧の並びを自分で持つ

チャンネル一覧の並び順に従った再生は、本来サムネイルが持つ `sequenceParams` で実現されている。
しかし `sequenceParams` は **SPA 遷移のメモリ上の状態としてのみ運ばれ、URL には乗らない**ため、
予防とは両立しない。そこで一覧の並びを自分で記憶する。

- 一覧でクリックした時点で、表示中の並び順そのままに動画 ID を記憶する（`sessionStorage`）。
  DOM に並んでいる順がそのまま選択中のソート順なので、ソート名を読む必要はない
- Shorts ページでは、ホイールと `ArrowDown` / `ArrowUp` を横取りして記憶した順に遷移する
- 描画済みの分を使い切ったら、チャンネルページを取り直して並び順どおりに一覧を延長する
  （`ytInitialData` → ソートチップの継続トークン → `/youtubei/v1/browse`）
- 記憶に無い動画では何もせず YouTube に任せる。先頭より前へは戻らない

### 是正: 安全網

**別動画への自動移動**: `/shorts/<ID>` に着地してから 4 秒以内に、ユーザー操作なしで
別の ID へ移った場合、400ms 待って自力で戻らなければフルロードで引き戻す。
YouTube 自身が元に戻すことがあるため、この待ちを入れている（実測で 3 件中 2 件が自己復帰）。
一度戻しても再び移動する場合は、それ以上介入しない（再読み込みループの防止）。

**黒画面**: 再生中の映像が表示領域から完全に外れているときだけ、中央に引き戻す。
一部でも見えていればスワイプ途中とみなして触らない。

## 隔離環境で完結させている理由

本体は既定の隔離環境（コンテンツスクリプト）で動く。ページ本体の実行環境は使わない。

開発中は、ページと同じ実行環境で `window.fetch` や `HTMLMediaElement.prototype.play` を
フックして計測していた。そのために 2 つの方式を試し、どちらも捨てた。

| 方式 | 結果 |
| --- | --- |
| `<script src="moz-extension://...">` をページに差し込む | **CSP に阻まれる。** YouTube の CSP には `strict-dynamic` が入っており、信頼済みスクリプトが読み込んだもの以外は実行されない |
| manifest の `"world": "MAIN"` | **効かない環境がある。** エラーも警告も出ないまま隔離環境で動き、ページ側からは何も見えない |

原因が判明した後は計測が不要になり、予防・順送り・是正はいずれも
DOM とイベントだけで実現できるため、隔離環境だけで完結する構成にした。
CSP の変更で突然動かなくなる、という壊れ方をしなくなる。

## 開発中の読み込み

1. Firefox のアドレスバーに `about:debugging#/runtime/this-firefox` を入力
2. 「一時的なアドオンを読み込む...」をクリック
3. このリポジトリの `manifest.json` を選択

一時的なアドオンは Firefox を再起動すると消える。

**ファイルを更新したら `about:debugging` の「再読み込み」を押すこと。**
押さないと古いコードが動き続ける。

## 動かないとき

まず、注入されているかを確認する。ページのコンソールで次を実行する。

```javascript
document.documentElement.dataset.cys
```

版番号が返れば動いている。`undefined` なら注入されていない。

### `undefined` のとき

**同じ ID のアドオンが `about:addons` に残っていないか確認する。** これが最も嵌まりやすい。

無効状態であっても、同じ ID のアドオンが登録されていると
`about:debugging` の一時アドオンは読み込まれない。**エラーも警告も出ない**まま
一覧には表示され、しかし注入だけされない、という壊れ方をする。
署名版を入れた後に一時アドオンへ戻す場合は、`about:addons` から署名版を
**完全に削除**すること。「無効化」では足りない。

その他の確認点。

- `about:debugging` で選ぶのは展開されたフォルダの `manifest.json`。
  `dist` の zip を選ぶと古い版が読み込まれる
- ファイル構成を変えたときは「再読み込み」ではなく一度「削除」してから読み込み直す
- コンテンツスクリプトは既に開いているページには後から注入されない。
  読み込み直したら対象のタブを再読み込みする

## 診断

隔離環境で動くため、`console.log` はページのコンソールに出ないことがある。
記録は `sessionStorage` に残るので、そちらを読むのが確実。

```javascript
JSON.parse(sessionStorage.getItem("__cys_log__"))    // 動作記録
JSON.parse(sessionStorage.getItem("__cys_order__"))  // 記憶している一覧の並び
```

DOM イベントを入口にした操作も用意している。出力はコンソールに `[CYS]` 付きで出る。

```javascript
document.dispatchEvent(new Event("cys-画面"))   // 映像の状態を出す
document.dispatchEvent(new Event("cys-ログ"))   // 記録を全部出す
document.dispatchEvent(new Event("cys-消去"))   // 記録を消す
```

`Ctrl+Shift+J` のブラウザーコンソールにも拡張機能のログが出る。

### 記録の種別

| 種別 | 意味 |
| --- | --- |
| `読み込み` | ページ読み込み時の版と URL |
| `一覧を記憶` | 一覧のクリック時に並び順を記憶した |
| `一覧を延長` | 記憶した一覧の続きを取得した |
| `一覧の延長に失敗` | 続きの取得に失敗した。記憶済みの範囲では動く |
| `通常遷移に切替` | Shorts のリンクを横取りしてページ遷移で開いた（予防） |
| `自前で順送り` | 記憶した並び順で次／前の Short へ遷移した |
| `順送りの終端` | 記憶を使い切った。以降は YouTube に任せる |
| `自動移動を検知` | ユーザー操作なしで別の ID に移った |
| `自己復帰` | 待っている間に YouTube 自身が戻したため介入しなかった |
| `是正` | フルロードで元の ID に戻した |
| `介入中止` | 是正済みの ID が再び移動したため受け入れた |
| `移動を許容` | ユーザー操作による移動、または猶予時間を過ぎた移動 |
| `画面外を是正` | 再生中の映像が表示領域の外にあったので中央に引き戻した |
| `画面状態(手動)` | `cys-画面` で出した映像の状態 |

記録は `sessionStorage` に保持されるため、ページのフルロードをまたいでも残る。
是正が働いた場合は新しい `読み込み` 行が現れる。

### 黒画面の切り分け

音声だけ流れて画面が真っ黒になったら、**その状態のまま** `cys-画面` を実行する。

| 出力 | 意味 |
| --- | --- |
| `解像度=0x0` または `復号=0` | 映像が復号できていない。デコーダ側の問題 |
| 解像度はあるが `枠=0x0` / `display=none` / `opacity=0` | 復号はできているが表示されていない |
| `主役が画面外` | 表示位置がずれている。是正の対象 |

## 調整できる値

`cys.js` の先頭付近。

| 定数 | 既定 | 意味 |
| --- | --- | --- |
| `常に通常遷移` | true | Shorts のリンクを通常のページ遷移で開く（予防）。false で是正のみ |
| `自前で順送り` | true | 記憶した並び順で次へ送る。false で YouTube の推薦順に任せる |
| `DEBUG` | false | true にすると全記録をコンソールに出す。false でも記録は残る |
| `GRACE_MS` | 4000 | 着地からこの時間内の移動だけを異常とみなす |
| `SETTLE_MS` | 400 | 検知から是正までの猶予。この間に自力で戻れば介入しない |
| `POLL_MS` | 50 | URL の監視間隔 |
| `REPAIR_MEMORY_MS` | 30000 | 同じ ID を直し続けないための有効期間 |
| `OFFSCREEN_CHECK_MS` | 1000 | 映像が画面外に無いか調べる間隔 |
| `OFFSCREEN_COOLDOWN_MS` | 3000 | 画面外の是正を連続で撃たないための間隔 |
| `NAV_COOLDOWN_MS` | 700 | 順送りを連続で撃たないための間隔 |
| `WHEEL_THRESHOLD` | 40 | ホイールをこの量ためたら 1 本送る |
| `REFILL_MARGIN` | 10 | 残りがこの本数を切ったら一覧の続きを取りに行く |

## リリース手順

### 1. パッケージを作る

```
powershell -ExecutionPolicy Bypass -File build.ps1
```

`dist\CertainlyOpenYoutubeShorts-<版>.zip` ができる。`manifest.json` が zip の直下にある必要があるため、
エクスプローラーでフォルダを右クリックして圧縮したものは**使えない**（フォルダが 1 階層挟まる）。

### 2. AMO にアップロードする

1. https://addons.mozilla.org/developers/ にログイン
2. 「新しいアドオンを登録」→ 配布方法を選ぶ
   - **公開する場合**: 「Mozilla で配布する」。審査に回り、AMO の一覧に載る
   - **自分だけで使う場合**: 「自分で配布する」（On your own）。署名済み `.xpi` が数分で手に入る
3. 手順 1 の zip をアップロード
4. [AMO掲載情報.md](AMO掲載情報.md) の文面を各欄に入力（公開する場合のみ）

ソースコードの提出は不要（難読化・minify をしていないため）。

### 3. 更新するとき

`manifest.json` の `version` と `cys.js` の `VERSION` を**両方**上げてから繰り返す。
AMO は同じ版番号の再アップロードを受け付けない。

### 注意

- 拡張機能 ID は `certainly-open-youtube-shorts@konamuki0852`
- `browser_specific_settings.gecko.data_collection_permissions` は AMO の必須項目。
  本アドオンは何も収集・送信しないため `{ "required": ["none"] }` を宣言している。
  これが無いと「The "data_collection_permissions" property is missing.」で検証に失敗する
- 検証に失敗した版番号は再利用できないことがある。指摘を直したら版番号も上げてから再提出する
- `build.ps1` は **UTF-8 BOM 付き**で保存すること。BOM が無いと Windows PowerShell 5.1 が
  CP932 として読み、日本語コメント末尾の全角文字が改行を飲み込んで**次の行が消える**。
  エラーも出ずに空の zip ができるので気付きにくい
